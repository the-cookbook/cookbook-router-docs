The `@cookbook/router/rendering` entrypoint is the renderer-neutral branch traversal API.

```ts ts2js
import { renderRouteMatch } from '@cookbook/router/rendering';

import type {
  RenderRouteMatchOptions,
  ResolvedRouteFallback,
  RouteBoundaryViewContext,
  RouteEmptyViewContext,
  RouteErrorViewContext,
  RouteInterceptViewContext,
  RouteLayoutViewContext,
  RouteLoadingViewContext,
  RouteSlotViewContext,
  RouteViewContext,
} from '@cookbook/router/rendering';
```

The package root re-exports the same rendering value and public rendering types.

Cookbook Router resolves what should render. It does not know how a framework renders it. `RouteView` is opaque. React components, server templates, lazy wrappers, string handles, virtual DOM nodes, or framework-specific records can all live there.

`renderRouteMatch()` traverses a resolved `RouteMatch` and asks an adapter to convert those opaque views into real output.

React uses this API internally. Other renderers can use it without reimplementing branch traversal, layout wrapping, slot resolution, interception, fallback ownership, or empty-state rules.

`@cookbook/router/rendering` exports this value:

## `renderRouteMatch()`

```ts ts2js
function renderRouteMatch<
  View = RouteView,
  Output = unknown,
>(
  match: RouteMatch | null | undefined,
  options: RenderRouteMatchOptions<View, Output>,
): Output;
```

Traverses a resolved route match and returns renderer output.

```ts ts2js
interface RenderRouteMatchOptions<
  View = RouteView,
  Output = unknown,
> {
  readonly error?: unknown;
  readonly fallback: Output;
  readonly renderView: (
    view: View,
    context: RouteViewContext<Output>,
  ) => Output;
  readonly renderLayout?: (
    view: View,
    context: RouteLayoutViewContext<Output>,
  ) => Output;
  readonly renderLoading?: (
    view: View,
    context: RouteLoadingViewContext<Output>,
  ) => Output;
  readonly renderError?: (
    view: View,
    context: RouteErrorViewContext<Output>,
  ) => Output;
  readonly renderSlot?: (
    view: View,
    context: RouteSlotViewContext<Output>,
  ) => Output;
  readonly renderIntercept?: (
    view: View,
    context: RouteInterceptViewContext<Output>,
  ) => Output;
  readonly renderBoundary?: (
    outlet: Output,
    context: RouteBoundaryViewContext<View, Output>,
  ) => Output;
  readonly renderEmpty?: (
    context: RouteEmptyViewContext,
  ) => Output;
}
```

A missing match is an empty state:

```ts ts2js
renderRouteMatch(null, {
  fallback: 'not-found',
  renderView: (view) => String(view),
});
// 'not-found'
```

With `renderEmpty`, the adapter owns the empty-state output:

```ts ts2js
renderRouteMatch(null, {
  fallback: 'fallback',
  renderView: (view) => String(view),
  renderEmpty(context) {
    return context.reason;
  },
});
// 'not-found'
```

## Minimal adapter example

```ts ts2js
import { renderRouteMatch } from '@cookbook/router/rendering';
import type { RouteView } from '@cookbook/router/route-config';

interface Node {
  readonly kind: string;
  readonly value?: unknown;
  readonly children?: readonly Node[];
}

const output = renderRouteMatch<RouteView, Node>(match, {
  fallback: {
    kind: 'empty',
  },

  renderView(view, context) {
    return {
      kind: 'route',
      value: {
        view,
        routeId: context.match.id,
      },
      children: [
        context.outlet,
        ...Object.values(context.slots),
      ],
    };
  },

  renderLayout(view, context) {
    return {
      kind: 'layout',
      value: {
        view,
        ownerRouteId: context.ownerRouteId,
      },
      children: [
        context.outlet,
        ...Object.values(context.slots),
      ],
    };
  },

  renderBoundary(content, context) {
    return {
      kind: 'boundary',
      value: {
        routeId: context.match.id,
        isLeaf: context.isLeaf,
        loadingOwner: context.loading?.match.id,
        errorOwner: context.error?.match.id,
      },
      children: [content],
    };
  },

  renderEmpty(context) {
    return {
      kind: context.reason,
    };
  },
});
```

The example is structural. It does not call a view. That is intentional.

Only an adapter knows whether a `RouteView` is a component, template, module reference, function, string key, or framework primitive.

## Traversal model

A `RouteMatch.branch` is stored root-to-leaf.

Traversal starts at the root branch entry, but each route first renders its child branch. The final output is assembled leaf-to-root.

For each branch entry, traversal does this:

1. Resolve layout loading/error fallbacks from the current route and inherited layout fallbacks.
2. Render the descendant branch into the current outlet.
3. Render named slots owned by the current route layout.
4. At the leaf, render `options.error` through the selected error fallback when one exists.
5. Otherwise render the route view, or pass the outlet through when no route view exists.
6. Wrap that content with `renderBoundary()` when provided.
7. Wrap the bounded content with the current layout view when one exists.

Route without a `view`:

```ts ts2js
{
  id: 'group',
  path: 'group',
  children: [
    {
      id: 'group.home',
      index: true,
      view: GroupHome,
    },
  ],
}
```

The `group` route passes its descendant outlet through.

Layout without a `view` also passes through. This is how pathless grouping routes stay renderer-neutral.

## Callback fallback behavior

Specialized callbacks fall back to `renderView()`:

| Specialized callback | Fallback     |
| -------------------- | ------------ |
| `renderLayout`       | `renderView` |
| `renderError`        | `renderView` |
| `renderSlot`         | `renderView` |
| `renderIntercept`    | `renderView` |

`renderLoading` is different. It does not fall back, because current traversal does not call it directly.

Loading views are surfaced through `renderBoundary()` metadata.

## Shared view context

```ts ts2js
interface RouteViewContext<Output = unknown> {
  readonly match: MatchedRoute;
  readonly outlet: Output;
  readonly slots: Readonly<Record<string, Output>>;
}
```

  type={{

`outlet` is callback-local:

| Callback          | `context.outlet` means                                                                 |
| ----------------- | -------------------------------------------------------------------------------------- |
| `renderView`      | Rendered descendant branch output.                                                     |
| `renderLayout`    | Rendered and boundary-wrapped route content for this layout.                           |
| `renderSlot`      | Slot fallback outlet; currently `options.fallback` for configured slot fallback views. |
| `renderIntercept` | Rendered intercepted target branch.                                                    |
| `renderError`     | Rendered descendant outlet for the route where the selected error fallback is owned.   |

Do not mutate `match`, `outlet`, or `slots`.

`renderLayout()` receives the layout shell view after the route content has been boundary-wrapped.

```ts ts2js
renderLayout(view, context) {
  return renderLayoutShell(view, {

    outlet: context.outlet,
```

When `renderLayout` is absent, traversal uses `renderView()` with the layout view.

`renderBoundary()` is where an adapter installs Suspense-like and error-boundary behavior.

```ts ts2js
renderBoundary(content, context) {
  return createBoundary({
    content,
    route: context.match,
    loading: context.loading,
    error: context.error,
    isLeaf: context.isLeaf,
  });
}
```

The first argument is the rendered content for the current branch entry.

`context.outlet` is the child outlet passed through the context object. Do not confuse the two.

Fallback ownership rules:

| Fallback field   | Ownership                                                   |
| ---------------- | ----------------------------------------------------------- |
| `route.loading`  | Selected only for that route's own leaf view.               |
| `route.error`    | Selected only for that route's own leaf view.               |
| `layout.loading` | Inherited by descendants rendered inside that layout shell. |
| `layout.error`   | Inherited by descendants rendered inside that layout shell. |

A selected fallback includes the match that owns it. That owner may differ from the leaf that suspended or errored.

When `renderBoundary` is omitted, traversal returns content without adapter boundaries.

/>

`RouteLoadingViewContext` and `renderLoading` are public contract members.

Current traversal does not invoke `renderLoading()` directly.

Instead, it passes loading fallback metadata to `renderBoundary()`:

```ts ts2js
renderBoundary(content, context) {
  const loading = context.loading;

  return installSuspenseBoundary(content, {
    fallbackView: loading?.view,
    fallbackRoute: loading?.match,
  });
}
```

Do not build an adapter that depends on direct `renderLoading()` invocation without checking the implementation version.

## Error context

```ts ts2js
interface RouteErrorViewContext<Output = unknown>
  extends RouteViewContext<Output> {
  readonly error: unknown;
  readonly source: 'route' | 'layout';
}
```

<TypeTable
  type={{
    error: {
      description: 'Router-state error passed through options.error.',
      type: 'unknown',
    },
    source: {
      description: 'Whether the selected error fallback came from route.error or layout.error.',
      type: "'route' | 'layout'",

  }}
/>

`options.error` is considered only at the leaf.

When a selected route/layout error fallback exists, traversal converts it with `renderError()` or `renderView()`.

```ts ts2js
renderError(view, context) {
  return renderErrorFallback(view, {
    error: context.error,
    route: context.match,
    source: context.source,
  });
}
```

When `options.error` exists and no error fallback exists, traversal renders an empty route state:

```ts ts2js
{
  reason: 'empty-route',
  match,
}
```

That empty state goes through `renderEmpty()` when supplied, otherwise `options.fallback`.

Thrown framework render errors are not caught by core traversal. They belong to the adapter boundary installed by `renderBoundary()`.

Slot behavior is driven by `ResolvedSlot.status`.

| Status                  | Rendering behavior                                                              |
| ----------------------- | ------------------------------------------------------------------------------- |
| `disabled`              | Empty state with `reason: 'disabled-slot'`.                                     |
| `empty`                 | Empty state with `reason: 'empty-slot'`.                                        |
| `not-found`             | Empty state with `reason: 'not-found'` and the slot attached.                   |
| `matched` with `branch` | Recursively renders the slot branch with no inherited primary-branch fallbacks. |
| `fallback` with `view`  | Converts the slot fallback through `renderSlot()` or `renderView()`.            |

Configured slot fallback example:

```ts ts2js
{
  id: 'dashboard',
  path: '/dashboard',
  layout: {
    view: DashboardLayout,
    slots: {
      sidebar: SidebarFallback,
    },
  },
}
```

When no sidebar slot route matches, traversal renders `SidebarFallback` as a slot view.

For configured slot fallbacks, traversal creates a synthetic `MatchedRoute` when `slot.fallback` exists.

Synthetic ID shape:

```text
${ownerRouteId}.${slotName}
```

Example:

```text
dashboard.sidebar
```

The synthetic match:

* uses the fallback view;
* carries fallback metadata;
* is marked as a slot route;
* receives params from the slot owner route.

That gives adapters and hooks a stable route context for fallback slot content.


  type={{

      type: 'string',

    name: {
      description: 'Slot name receiving the intercepted route.',
      type: 'string',

      type: 'ResolvedInterceptedRoute',

    },
  }}

An active intercepted route wins before ordinary slot rendering when it targets the current owner and slot.

Traversal:

1. detects `match.intercepted`;
2. checks that `intercepted.slot` matches the slot being rendered;
3. checks that `intercepted.sourceRouteId` matches the current slot owner;
4. recursively renders the intercepted target branch as `context.outlet`;
5. converts the intercept shell through `renderIntercept()` or `renderView()`;
6. wraps the intercept shell in its own boundary.

```ts ts2js
renderIntercept(view, context) {
  return renderModalShell(view, {
    ownerRouteId: context.ownerRouteId,
    slotName: context.name,
    target: context.intercepted.targetRouteId,
    outlet: context.outlet,
    context: context.context,
  });
}
```

Direct visits to an intercepted target are not intercepted by this traversal. Interception exists only when the resolved match carries `intercepted` state.

## Empty context

```ts ts2js
interface RouteEmptyViewContext {
  readonly reason:
    | 'empty-branch'
    | 'empty-route'
    | 'empty-slot'
    | 'disabled-slot'
    | 'not-found';
  readonly match?: MatchedRoute;
  readonly slot?: ResolvedSlot;
}
```

<TypeTable
  type={{
    reason: {
      description: 'Why traversal had no renderable output at this point.',
      type: "'empty-branch' | 'empty-route' | 'empty-slot' | 'disabled-slot' | 'not-found'",
    },
    match: {
      description: 'Associated matched route when the empty state belongs to a route.',
      type: 'MatchedRoute',

      type: 'ResolvedSlot',
      optional: true,
    },

Empty-state reasons:

| Reason          | Meaning                                                       |
| --------------- | ------------------------------------------------------------- |
| `not-found`     | No primary match, or a resolved slot state says not-found.    |
| `empty-branch`  | Traversal reached the end of a branch without a branch entry. |
| `empty-route`   | A route-level render position has no renderable output.       |
| `empty-slot`    | Slot has no matched route or fallback output.                 |
| `disabled-slot` | Slot state is disabled.                                       |

When `renderEmpty` is absent, every empty state returns `options.fallback`.

That is often wrong for UI adapters. A page-level not-found might be a visible fallback, while an empty slot should usually be `null`.

```ts ts2js
renderEmpty(context) {
  if (
    context.reason === 'not-found' &&
    context.slot === undefined
  ) {
    return pageNotFound();
  }

  return nullOutput();
}
```

## Route-state errors

`options.error` renders a router-state error at the active leaf.

```ts ts2js
const output = renderRouteMatch(match, {
  error: navigationError,
  fallback: empty(),
  renderView,
  renderError(view, context) {
    return renderErrorView(view, {
      error: context.error,
      route: context.match,
    });
  },
});
```

Route-local error fallback:

```ts ts2js
{
  id: 'home',
  path: '/',
  view: HomePage,
  error: HomeError,
}
```

Layout-level inherited error fallback:

```ts ts2js
{
  id: 'root',
  path: '/',
  layout: {
    view: RootLayout,
    error: RootError,
  },
  children: [
    {
      id: 'home',
      index: true,
      view: HomePage,
    },
  ],
}
```

When the leaf has a route-level error fallback, it wins.

When the leaf does not, the nearest inherited layout error fallback is used.

When no error fallback exists, traversal renders `empty-route`.

## Loading fallbacks

`renderRouteMatch()` does not render loading fallback views itself.

It resolves ownership and passes metadata to `renderBoundary()`.

```ts ts2js
renderBoundary(content, context) {
  if (context.loading) {
    return installAsyncBoundary(content, {
      fallback: context.loading.view,
      owner: context.loading.match,
      source: context.loading.source,
    });
  }

  return content;
}
```

Route-local loading fallback:

```ts ts2js
{
  id: 'users.details',
  path: '/users/{id:int}',
  view: UserDetails,
  loading: UserDetailsLoading,
}
```

Layout-level inherited loading fallback:

```ts ts2js
{
  id: 'dashboard',
  path: '/dashboard',
  layout: {
    view: DashboardLayout,
    loading: DashboardLoading,
  },
  children: [
    {
      id: 'dashboard.analytics',
      path: 'analytics',
      view: AnalyticsPage,
    },
  ],
}
```

A route-level loading fallback is selected for that route’s own leaf view. A layout loading fallback can be inherited by descendants rendered inside that layout shell.

## Slot and intercept example

```ts ts2js
const output = renderRouteMatch(match, {
  fallback: empty(),

  renderView(view, context) {
    return routeNode(view, {
      routeId: context.match.id,
      outlet: context.outlet,
    });
  },

  renderLayout(view, context) {
    return layoutNode(view, {
      ownerRouteId: context.ownerRouteId,
      outlet: context.outlet,
      slots: context.slots,
    });
  },

  renderSlot(view, context) {
    return slotNode(view, {
      ownerRouteId: context.ownerRouteId,
      name: context.name,
      params: context.params,
    });
  },

  renderIntercept(view, context) {
    return interceptNode(view, {
      ownerRouteId: context.ownerRouteId,
      name: context.name,
      targetRouteId:
        context.intercepted.targetRouteId,
      outlet: context.outlet,
      context: context.context,
    });
  },

  renderEmpty(context) {
    return empty(context.reason);
  },
});
```

This example still does not call `view`.

Calling a view is renderer-specific.

## What this API does not do

`renderRouteMatch()` does not:

* match a URL;
* parse search or hash state;
* run middleware;
* run lifecycle hooks;
* preload route modules;
* catch thrown framework render errors by itself;
* install Suspense;
* install an error boundary;
* call React, Vue, Solid, Svelte, or any other renderer;
* decide whether a `RouteView` is callable.

It traverses an already-resolved match and delegates conversion.

## Where this bites

### `renderLoading()` is not called

This will not run in the current traversal:

```ts ts2js
renderRouteMatch(match, {
  fallback,
  renderView,
  renderLoading(view, context) {
    return renderLoadingView(view, context);
  },
});
```

Use `renderBoundary()` and read `context.loading`.

### `options.error` is leaf-only

This renders a router-state error at the active leaf:

```ts ts2js
renderRouteMatch(match, {
  error,
  fallback,
  renderView,
  renderError,
});
```

It does not catch framework render exceptions thrown by views.

Adapters must install their own boundary in `renderBoundary()`.

### Empty slots become `fallback` unless you override them

Without `renderEmpty`, empty slots return `options.fallback`.

For UI adapters, that usually paints the page not-found UI inside a slot.

Use `renderEmpty()`:

```ts ts2js
renderEmpty(context) {
  if (context.slot) {
    return nullOutput();
  }

  return notFoundOutput();
}
```

### The boundary argument is not the same as `context.outlet`

```ts ts2js
renderBoundary(content, context) {
  // content: current rendered route/intercept/slot content
  // context.outlet: child outlet carried in context
}
```

Adapters that wrap the wrong one install boundaries around the wrong part of the tree.

### Route views are opaque

This is wrong in core-level adapter code:

```ts ts2js
view(context);
```

Some renderers use functions. Some use components. Some use module records. Some use lazy wrappers. Some use strings.

Only the adapter knows how to convert `RouteView` into output.
