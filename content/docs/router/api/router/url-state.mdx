The `@cookbook/router/url-state` entrypoint is the narrow bridge between Cookbook Router and URLKit.

It compiles route URL descriptors, resolves layered URL policy, and exposes low-level helpers for parsing and building route path, search, and hash state.

It is not the whole router. It does not rank routes, run middleware, commit navigation, preload modules, or render anything.

```ts
import {
  buildRouteHash,
  buildRoutePath,
  buildRouteSearch,
  createRouteUrlContract,
  parseRouteHash,
  parseRoutePathParams,
  parseRouteSearch,
  parseRouteSearchState,
  parseRouteUrlState,
  resolveRouteUrlOptions,
  resolveUrlOptions,
} from '@cookbook/router/url-state';
```

The package root re-exports only the common URL-state helpers:

```ts
import {
  createRouteUrlContract,
  resolveUrlOptions,
} from '@cookbook/router';
```

There is no `registerUrlPathConstraints()` export. For custom path constraints, either pass `pathConstraints` to the operation that compiles the contract, or register them through the path API.

```ts
import { registerPathConstraints } from '@cookbook/router/path';
```

## `createRouteUrlContract(route, options?)`

```ts
interface RouterRouteUrlDescriptor {
  readonly path?: string;
  readonly search?: RouteSearchSchema;
  readonly hash?: RouteHashSchema;
  readonly url?: RouterUrlOptions;
}

interface CreateRouterRouteUrlContractOptions {
  readonly routerUrl?: RouterUrlOptions;
  readonly callUrl?: RouterUrlOptions;
  readonly pathConstraints?: RouterPathConstraints;
  readonly routeId?: string;
}

function createRouteUrlContract(
  route: RouterRouteUrlDescriptor,
  options?: CreateRouterRouteUrlContractOptions,
): RouterRouteUrlContract;
```

Compiles one static route URL descriptor into the URLKit contract used by route matching and href generation.

<TypeTable
  type={{
    routerUrl: {
      description: 'Router-level URL policy. Lowest precedence.',
      type: 'RouterUrlOptions',
      optional: true,
    },
    callUrl: {
      description: 'Per-call URL policy. Highest precedence.',
      type: 'RouterUrlOptions',
      optional: true,
    },
    pathConstraints: {
      description: 'Custom path constraints available while compiling and matching this contract.',
      type: 'RouterPathConstraints',
      optional: true,
    },
    routeId: {
      description: 'Route ID used only to improve URL descriptor diagnostics.',
      type: 'string',
      optional: true,
    },
  }}
/>

```ts
import { createRouteUrlContract } from '@cookbook/router/url-state';

const contract = createRouteUrlContract(
  {
    path: '/articles/{id:int}',
    search: {
      page: {
        type: 'int',
        default: 1,
      },
      featured: {
        type: 'boolean',
        optional: true,
      },
      tags: {
        type: 'string',
        many: true,
      },
    },
    hash: {
      type: 'enum',
      values: ['comments', 'share'],
      optional: true,
    },
  },
  {
    routeId: 'articles.show',
  },
);

const state = contract.parse(
  '/articles/42?page=2&tags=router&tags=typescript#comments',
);

const href = contract.build({
  params: {
    id: 42,
  },
  search: {
    page: 2,
    tags: ['router', 'typescript'],
  },
  hash: 'comments',
});
```

Path parameters are compiled in parsed mode. A path such as `{id:int}` produces a numeric `id`, not the source string `'42'`.

```ts
contract.parsePathname('/articles/42');
// { id: 42 }
```

### Option precedence

The effective URL policy is merged in this order, from lowest to highest priority:

1. `options.routerUrl`
2. `route.url`
3. `options.callUrl`

Only supplied fields override lower layers. Omitted fields stay omitted so URLKit defaults remain authoritative.

```ts
const contract = createRouteUrlContract(
  {
    path: '/products',
    search: {
      tags: {
        type: 'string',
        many: true,
      },
    },
    url: {
      arrayFormat: 'comma',
    },
  },
  {
    routerUrl: {
      arrayFormat: 'repeat',
    },
    callUrl: {
      arrayFormat: 'repeat',
    },
  },
);

contract.build({
  search: {
    tags: ['router', 'typescript'],
  },
});
// '/products?tags=router&tags=typescript'
```

### Custom path constraints

Prefer passing constraints directly when compiling the contract:

```ts
import { createPathConstraint } from '@cookbook/router/path';
import { createRouteUrlContract } from '@cookbook/router/url-state';

const slug = createPathConstraint({
  parse(paramName, value) {
    if (
      typeof value !== 'string' ||
      !/^[a-z0-9-]+$/.test(value)
    ) {
      throw new Error(
        `Parameter "${paramName}" must be a valid slug.`,
      );
    }
  },
  verify(_paramName, params) {
    if (params) {
      throw new Error('slug does not accept parameters.');
    }
  },
  toRegExp() {
    return '[a-z0-9-]+';
  },
});

const contract = createRouteUrlContract(
  {
    path: '/posts/{slug:slug}',
  },
  {
    pathConstraints: {
      slug,
    },
    routeId: 'posts.show',
  },
);
```

`createRouteUrlContract()` registers supplied constraints with the shared path registry and passes them into the compiled URLKit contract.

Existing compiled contracts are immutable. Registering a constraint later does not rebuild a contract that already exists.

### Date and date-time descriptors

Router forwards static date and date-time formats to URLKit without rewriting tokens.

```ts
const contract = createRouteUrlContract({
  path: '/reports',
  search: {
    from: {
      type: 'date',
      format: 'dd-MM-yyyy',
      optional: true,
    },
    at: {
      type: 'date-time',
      format: 'dd-MM-yyyy HH:mm:ss',
      optional: true,
    },
  },
});
```

Format tokens are case-sensitive.

`DD-MM-yyyy` is not the same as `dd-MM-yyyy`.

Invalid descriptor formats fail contract creation. The route should break at setup, not after a user follows a link.

### Diagnostic behavior

When URLKit rejects a descriptor, Router preserves the URLKit error code and path when available, attaches the original error as `cause`, and adds route context.

```text
Route "reports" has an invalid URL descriptor. ...
```

`routeId` affects diagnostics only. It does not change matching, ranking, parsing, or href generation.

## `RouterRouteUrlContract`

```ts
interface RouterRouteUrlContract {
  readonly pattern: string | undefined;

  parse(
    input: string | URL,
    options?: RouterRouteSearchParseOptions,
  ): unknown;

  match(
    input: string | URL,
    options?: RouterRouteSearchParseOptions,
  ): boolean;

  build(
    input: unknown,
    options?: RouterUrlBuildOptions,
  ): string;

  parsePathname:
    | ((
        pathname: string,
        options?: RouterPathMatchOptions,
      ) => unknown)
    | never;

  buildPath:
    | ((params: unknown) => string)
    | never;

  parseSearch(
    input: string | URLSearchParams,
    options?: RouterRouteSearchParseOptions,
  ): unknown;

  buildSearch(
    search: unknown,
    options?: RouterUrlBuildOptions,
  ): string;

  parseHash(input: unknown): unknown;

  buildHash(
    hash?: unknown,
    options?: RouterUrlBuildOptions,
  ): string;
}
```

| Member          | Responsibility                                                                                        |
| --------------- | ----------------------------------------------------------------------------------------------------- |
| `pattern`       | Compiled path pattern, or `undefined` for a pathless descriptor.                                      |
| `parse`         | Parses pathname, declared search, unknown search state, and declared hash as one URL-state operation. |
| `match`         | Returns whether the full input satisfies the contract under parse options.                            |
| `build`         | Serializes params, search, and hash into one href.                                                    |
| `parsePathname` | Parses path params with route constraints and path-match options.                                     |
| `buildPath`     | Serializes path params into a pathname.                                                               |
| `parseSearch`   | Parses only the query string.                                                                         |
| `buildSearch`   | Serializes only declared search state.                                                                |
| `parseHash`     | Parses only hash state.                                                                               |
| `buildHash`     | Serializes only hash state.                                                                           |

The return types are deliberately `unknown`. Route-specific types come from generated Router contracts. This low-level API cannot infer a registered route ID from an arbitrary runtime descriptor.

Pathless descriptors expose path operations as `never` at the public contract boundary. Do not call `parsePathname()` or `buildPath()` unless the descriptor defines `path`.

## URL policy contracts

### `RouterUrlArrayFormat`

```ts
type RouterUrlArrayFormat =
  | 'repeat'
  | 'comma';
```

| Value      | Example                        |
| ---------- | ------------------------------ |
| `'repeat'` | `?tags=router&tags=typescript` |
| `'comma'`  | `?tags=router,typescript`      |

### `RouterInvalidUrlStatePolicy`

```ts
type RouterInvalidUrlStatePolicy =
  | 'recover'
  | 'no-match'
  | 'error';
```

Controls how invalid declared search or hash state is handled after the path has already matched.

| Policy       | Runtime meaning                                                                                                          |
| ------------ | ------------------------------------------------------------------------------------------------------------------------ |
| `'recover'`  | Keep the path candidate when URLKit can omit malformed optional or defaulted fields. Required invalid fields still fail. |
| `'no-match'` | Reject the route candidate so route matching can continue.                                                               |
| `'error'`    | Keep the route candidate and surface the parse failure through router error state.                                       |

At the low-level contract/helper layer, both `'no-match'` and `'error'` map to strict URLKit parsing. The router runtime decides whether that strict parse failure rejects the candidate or becomes error state.

### `RouterUnknownSearchPolicy`

```ts
type RouterUnknownSearchPolicy =
  | 'strip'
  | 'preserve'
  | 'error';
```

Controls query-string keys not declared by the route search schema.

| Policy       | Runtime meaning                                       |
| ------------ | ----------------------------------------------------- |
| `'strip'`    | Remove undeclared keys from declared search state.    |
| `'preserve'` | Keep undeclared keys in sibling unknown-search state. |
| `'error'`    | Reject input containing undeclared keys.              |

### `RouterUnknownSearchParams`

```ts
type RouterUnknownSearchParams =
  Record<string, unknown>;
```

Unknown query-string keys preserved when the effective `unknownSearch` policy is `'preserve'`.

Example router-level policy:

```ts
const router = createRouter({
  routes,
  url: {
    arrayFormat: 'repeat',
    invalidSearch: 'recover',
    invalidHash: 'recover',
    unknownSearch: 'strip',
  },
});
```

Route-level override:

```ts
{
  id: 'products',
  path: '/products',
  search: {
    tags: {
      type: 'string',
      many: true,
      optional: true,
    },
  },
  url: {
    arrayFormat: 'comma',
    unknownSearch: 'preserve',
  },
}
```

Unsupported path-match prefix mode:

```ts
url: {
  pathMatch: {
    end: false,
  },
}
```

This throws:

```text
Router url.pathMatch.end: false is not supported yet. Prefix matching requires route match state to expose consumed and remaining pathnames.
```

## `RouterRouteSearchParseOptions`

```ts
interface RouterRouteSearchParseOptions
  extends RouterPathMatchOptions {
  readonly arrayFormat?: RouterUrlArrayFormat;
  readonly unknownSearch?: RouterUnknownSearchPolicy;
  readonly invalidSearch?: 'error' | 'omit';
}
```

This is the lower-level URLKit parse shape after Router maps route-resolution policy.

It is not the same as `RouterUrlOptions`.

| Router policy                         | Contract parse behavior  |
| ------------------------------------- | ------------------------ |
| `invalidSearch: 'recover'` or omitted | `invalidSearch: 'omit'`  |
| `invalidSearch: 'error'`              | `invalidSearch: 'error'` |
| `invalidSearch: 'no-match'`           | `invalidSearch: 'error'` |

`'recover'` and `'no-match'` are router decisions. The URL contract only receives URLKit parse behavior.

## `resolveUrlOptions(input?)`

```ts
interface ResolveUrlOptionsInput {
  readonly router?: RouterUrlOptions;
  readonly route?: RouterUrlOptions;
  readonly call?: RouterUrlOptions;
}

function resolveUrlOptions(
  input?: ResolveUrlOptionsInput,
): RouterUrlOptions;
```

Performs the Router URL policy merge.

<TypeTable
  type={{
    router: {
      description: 'Router-level URL policy. Lowest precedence.',
      type: 'RouterUrlOptions',
      optional: true,
    },
    route: {
      description: 'Route-level URL policy. Overrides router policy.',
      type: 'RouterUrlOptions',
      optional: true,
    },
    call: {
      description: 'Per-call URL policy. Highest precedence.',
      type: 'RouterUrlOptions',
      optional: true,
    },
  }}
/>

```ts
import { resolveUrlOptions } from '@cookbook/router/url-state';

const options = resolveUrlOptions({
  router: {
    arrayFormat: 'repeat',
    unknownSearch: 'strip',
  },
  route: {
    arrayFormat: 'comma',
    unknownSearch: 'preserve',
  },
  call: {
    unknownSearch: 'error',
  },
});

// {
//   arrayFormat: 'comma',
//   unknownSearch: 'error',
// }
```

This utility is a shallow merge.

It does not inject defaults and does not validate the resulting policy. Contract creation and the consuming runtime operation own that work.

## `resolveRouteUrlOptions(route, options)`

```ts
function resolveRouteUrlOptions(
  route: NormalizedRoute,
  options: RouteUrlStateOptions,
): RouterUrlOptions;
```

Resolves effective URL policy for one normalized route operation.

The merge order is:

1. `options.routerUrl`
2. `route.route.url`
3. `options.callUrl`

```ts
const url = resolveRouteUrlOptions(route, {
  routerUrl: {
    arrayFormat: 'repeat',
    unknownSearch: 'strip',
  },
  callUrl: {
    unknownSearch: 'preserve',
  },
});
```

Route-level `url` lives on the original authored route definition stored under `normalized.route`.

## `parseRoutePathParams(route, pathname, options?)`

```ts
function parseRoutePathParams(
  route: NormalizedRoute,
  pathname: string,
  options?: RouteUrlStateOptions,
): Record<string, unknown> | null;
```

Attempts to parse path params for one normalized route.

Returns `null` when path parsing fails.

```ts
const params = parseRoutePathParams(
  route,
  '/users/42',
);

// { id: 42 }
```

Failed parse:

```ts
parseRoutePathParams(
  route,
  '/users/not-a-number',
);
// null
```

Wildcard params normalize to arrays:

```ts
parseRoutePathParams(
  filesRoute,
  '/files/docs/readme',
);
// { path: ['docs', 'readme'] }
```

With decoding:

```ts
parseRoutePathParams(
  filesRoute,
  '/files/a%2Fb/c%20d',
  {
    callUrl: {
      pathMatch: {
        decode: true,
      },
    },
  },
);
// { path: ['a/b', 'c d'] }
```

## `buildRoutePath(route, params, options?)`

```ts
function buildRoutePath(
  route: NormalizedRoute,
  params: unknown,
  options?: RouteUrlStateOptions,
): string;
```

Builds a pathname for one normalized route.

```ts
buildRoutePath(
  userRoute,
  {
    id: 42,
  },
);
// '/users/42'
```

Wildcard params can be strings or arrays:

```ts
buildRoutePath(
  filesRoute,
  {
    path: ['docs', 'readme'],
  },
);
// '/files/docs/readme'

buildRoutePath(
  filesRoute,
  {
    path: 'docs/readme',
  },
);
// '/files/docs/readme'
```

If the normalized route full path ends with a trailing slash, Router preserves that trailing slash after URLKit path building.

## `parseRouteSearch(route, search, options?)`

```ts
function parseRouteSearch(
  route: NormalizedRoute,
  search: string,
  options?: RouteUrlStateOptions,
): Record<string, unknown>;
```

Parses search state for one normalized route.

When the route has a declared search schema, URLKit validates and coerces the declared fields.

```ts
parseRouteSearch(
  productsRoute,
  '?tags=router,typescript',
  {
    callUrl: {
      arrayFormat: 'comma',
    },
  },
);
// { tags: ['router', 'typescript'] }
```

By default, invalid optional or defaulted fields recover when URLKit can omit or default them.

```ts
parseRouteSearch(
  overviewRoute,
  '?page=a&pageSize=10',
);
// { page: 1, pageSize: 10 }
```

Invalid required fields still throw:

```ts
parseRouteSearch(
  reportsRoute,
  '?page=a',
);
// throws: Expected a finite number value
```

`parseRouteSearch()` returns declared search only. It does not return the sibling `unknownSearch` value. Use `parseRouteSearchState()` when you need preserved undeclared query params.

## `parseRouteSearchState(route, pathname, search, options?)`

```ts
function parseRouteSearchState(
  route: NormalizedRoute,
  pathname: string,
  search: string,
  options?: RouteUrlStateOptions,
): ParsedRouteSearchState;
```

Parses declared search and returns preserved unknown search when available.

```ts
const state = parseRouteSearchState(
  productsRoute,
  '/products',
  '?page=1&debug=true',
  {
    callUrl: {
      unknownSearch: 'preserve',
    },
  },
);

// {
//   search: { page: 1 },
//   unknownSearch: { debug: 'true' },
// }
```

The `pathname` is required because schema-backed parsing uses the full route URL contract. It must match the route path.

When a route has no search schema, the helper returns generic parsed search state. Do not expect unknown keys to be split from declared keys when there is no declared search schema.

## `buildRouteSearch(route, search, options?)`

```ts
function buildRouteSearch(
  route: NormalizedRoute,
  search: unknown,
  options?: RouteUrlStateOptions,
): string;
```

Builds a query string for one normalized route.

```ts
buildRouteSearch(
  productsRoute,
  {
    tags: ['router', 'typescript'],
  },
  {
    callUrl: {
      arrayFormat: 'repeat',
    },
  },
);
// '?tags=router&tags=typescript'
```

Search keys are sorted while building route search so generated output is stable.

Defaults are controlled by `defaults`.

```ts
buildRouteSearch(
  overviewRoute,
  {
    page: 1,
  },
  {
    callUrl: {
      defaults: 'omit',
    },
  },
);
// ''
```

## `parseRouteHash(route, hash, options?)`

```ts
function parseRouteHash(
  route: NormalizedRoute,
  hash: string,
  options?: RouteUrlStateOptions,
): unknown;
```

Parses hash state for one normalized route.

For schema-backed hashes, URLKit validates and coerces the descriptor.

```ts
parseRouteHash(
  productsRoute,
  '#grid',
);
// 'grid'
```

By default, invalid optional/defaulted hash values recover.

```ts
parseRouteHash(
  productsRoute,
  '#missing',
);
// undefined
```

Strict hash behavior throws:

```ts
parseRouteHash(
  productsRoute,
  '#missing',
  {
    callUrl: {
      invalidHash: 'error',
    },
  },
);
// throws
```

When a route has no hash schema, Router normalizes the hash and preserves unrestricted hash values.

## `buildRouteHash(route, hash, options?)`

```ts
function buildRouteHash(
  route: NormalizedRoute,
  hash: unknown,
  options?: RouteUrlStateOptions,
): string;
```

Builds a hash string for one normalized route.

It accepts bare or `#`-prefixed input and returns a normalized hash string.

```ts
buildRouteHash(
  productsRoute,
  'grid',
);
// '#grid'

buildRouteHash(
  productsRoute,
  '#grid',
);
// '#grid'
```

For schema-backed hashes, defaults are controlled by build options.

## `parseRouteUrlState(route, pathname, search, hash, options?)`

```ts
function parseRouteUrlState(
  route: NormalizedRoute,
  pathname: string,
  search: string,
  hash: string,
  options?: RouteUrlStateOptions,
): ParsedRouteUrlState;
```

Parses path params, declared search, unknown search, and hash in one operation.

```ts
const state = parseRouteUrlState(
  userRoute,
  '/users/42',
  '?tab=activity&utm_source=docs',
  '#details',
  {
    callUrl: {
      unknownSearch: 'preserve',
    },
  },
);

// {
//   params: { id: 42 },
//   search: { tab: 'activity' },
//   unknownSearch: { utm_source: 'docs' },
//   hash: 'details',
// }
```

Unlike `parseRoutePathParams()`, this helper throws when path parsing fails. It is a route-state parser, not a nullable route candidate test.

Use `matchRoutes()` or router matching when you need candidate selection.

## Related descriptor helpers

Search and hash descriptor helpers are related to URL state, but they are root exports.

```ts
import {
  defineHash,
  defineSearch,
  mergeSearch,
} from '@cookbook/router';
```

They are not exported from `@cookbook/router/url-state`.

```ts
// Wrong.
import {
  defineSearch,
} from '@cookbook/router/url-state';
```

## Where this bites

### The URL-state subpath is public

This is valid:

```ts
import {
  parseRouteUrlState,
} from '@cookbook/router/url-state';
```

The old “root-only” wording is wrong.

### `registerUrlPathConstraints()` does not exist

This is wrong:

```ts
import {
  registerUrlPathConstraints,
} from '@cookbook/router/url-state';
```

Use path constraints directly:

```ts
createRouteUrlContract(
  {
    path: '/posts/{slug:slug}',
  },
  {
    pathConstraints: {
      slug,
    },
  },
);
```

or register globally through the path API:

```ts
import {
  registerPathConstraints,
} from '@cookbook/router/path';
```

### `parseRouteSearch()` drops the unknown-search sibling

This parses declared search:

```ts
parseRouteSearch(
  productsRoute,
  '?page=1&debug=true',
  {
    callUrl: {
      unknownSearch: 'preserve',
    },
  },
);
```

Use this when you need undeclared keys:

```ts
parseRouteSearchState(
  productsRoute,
  '/products',
  '?page=1&debug=true',
  {
    callUrl: {
      unknownSearch: 'preserve',
    },
  },
);
```

### `invalidSearch: 'no-match'` is not visible at the bare contract layer

Low-level parse helpers throw for both strict modes:

```ts
invalidSearch: 'error'
invalidSearch: 'no-match'
```

The router runtime decides whether a strict parse failure becomes route error state or candidate rejection.

### `pathMatch.end: false` is not supported

This is rejected:

```ts
url: {
  pathMatch: {
    end: false,
  },
}
```

Prefix matching requires match state that exposes consumed and remaining pathnames. The current URL-state bridge does not expose that.

### Existing contracts do not update after constraint registration

This is too late:

```ts
const contract = createRouteUrlContract({
  path: '/posts/{slug:slug}',
});

registerPathConstraints({
  slug,
});
```

Compile the contract with the constraint map, or register constraints before contract creation.
