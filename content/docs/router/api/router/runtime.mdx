The `@cookbook/router/runtime` entrypoint creates router instances and exposes runtime helpers for metadata and hydration state.

```ts
import {
  createMemoryRouter,
  createRouter,
  createStaticRouter,
  deserializeRouterState,
  getActiveRouteMetaChain,
  getRouteMeta,
  getRouteMetaChain,
  mergeRouteMetaChain,
  serializeRouterState,
  stringifyRouterState,
} from '@cookbook/router/runtime';
```

The package root re-exports the same runtime values.

Use the runtime API when you need an actual router: browser navigation, memory tests, SSR request resolution, preloading, middleware, blockers, route matching, and serialized hydration state.

## `createRouter(options)`

```ts
interface CreateRouterOptions {
  readonly routes: readonly RouteDefinition[];
  readonly basename?: string;
  readonly middleware?: readonly Middleware[];
  readonly lifecycle?: GlobalLifecycle;
  readonly hydrationData?: SerializedRouterState;
  readonly history?: RouterHistory;
  readonly pathOptions?: RouterPathOptions;
  readonly pathConstraints?: RouterPathConstraints;
  readonly url?: RouterUrlOptions;
  readonly maxRedirectDepth?: number;
  readonly maxRedirectionDepth?: number;
}

function createRouter(
  options: CreateRouterOptions,
): Router;
```

Creates a browser-capable router runtime.

Without an explicit `history`, it uses browser history when `window` exists and memory history otherwise.

```ts
import { createRouter } from '@cookbook/router/runtime';
import { routes } from './routes';

export const router = createRouter({
  routes,
});
```

With runtime options:

```ts
import { createRouter } from '@cookbook/router/runtime';

export const router = createRouter({
  routes,
  basename: '/app',
  middleware: [authMiddleware],
  lifecycle: {
    beforeNavigate(context) {
      analytics.track('route:start', {
        to: context.to?.id,
      });
    },
  },
  url: {
    arrayFormat: 'repeat',
    invalidSearch: 'recover',
    invalidHash: 'recover',
    unknownSearch: 'strip',
  },
  maxRedirectDepth: 10,
});
```

## `createMemoryRouter(options)`

```ts
interface CreateMemoryRouterOptions
  extends Omit<CreateRouterOptions, 'history'>,
    MemoryHistoryOptions {}

interface MemoryHistoryOptions {
  readonly initialEntries?: readonly string[];
  readonly initialIndex?: number;
}

function createMemoryRouter(
  options: CreateMemoryRouterOptions,
): Router;
```

Creates a router backed by memory history.

Use it for tests, stories, examples, and non-browser flows.

```ts
import { createMemoryRouter } from '@cookbook/router/runtime';

const router = createMemoryRouter({
  routes,
  initialEntries: [
    '/users/42?tab=settings#profile',
  ],
});
```

<TypeTable
  type={{

      type: 'readonly string[]',
      default: "['/']",
      optional: true,
    },
    initialIndex: {

`hydrationData` wins over `initialEntries` and `initialIndex`.

```ts
const serverState = staticRouter.serialize();

const router = createMemoryRouter({
  routes,
  hydrationData: serverState,
  initialEntries: ['/ignored'],
});
```

The memory history starts at `serverState.location.href`.

## `createStaticRouter(options)`

```ts
type StaticRouterUrl =
  | string
  | URL
  | Request;

interface CreateStaticRouterOptions
  extends Omit<CreateRouterOptions, 'history' | 'url'> {
  readonly url?: StaticRouterUrl;
  readonly request?: Request;
  readonly routerUrl?: RouterUrlOptions;
}

function createStaticRouter(
  options: CreateStaticRouterOptions,
): Router;
```

Creates a router backed by static history.

Use it for SSR and static request resolution.

```ts
import {
  createStaticRouter,
} from '@cookbook/router/runtime';

export async function renderRequest(request: Request) {
  const router = createStaticRouter({
    routes,
    request,
    routerUrl: {
      unknownSearch: 'preserve',
    },
  });

  await router.start();

  return router;
}
```

<TypeTable
  type={{
    url: {
      description: 'Static request location. Accepts a string, URL, or Request.',
      type: 'StaticRouterUrl',
      optional: true,
    },
    request: {
      description: 'Request object for SSR request resolution. Takes precedence over url.',
      type: 'Request',
      optional: true,
    },
    routerUrl: {
      description: 'Router-level URL policy for static rendering flows. Named routerUrl because url is the request location.',
      type: 'RouterUrlOptions',
      optional: true,
    },
  }}
/>

At least one of `request` or `url` is required.

Missing input throws:

```text
createStaticRouter requires either url or request.
```

`request` takes precedence over `url` when both are supplied.

Static URLs are normalized to `pathname + search + hash`.

```ts
const router = createStaticRouter({
  routes,
  url: new URL(
    'https://example.test/users/42?tab=settings#profile',
  ),
});

router.state.location.href;
// '/users/42?tab=settings#profile'
```

Unsafe protocols are rejected before static history is created.

```ts
createStaticRouter({
  routes,
  url: 'javascript:alert(1)',
});
```

Error:

```text
Static router URL must use http, https, or a relative path, but received protocol "javascript:".
```

`createStaticRouter()` uses `routerUrl` instead of `url` for URL policy because `url` already names the request location.

## `router.href()`

```ts
router.href(routeId, options?)
router.href(options)
```

Builds a URL for a route ID without changing state.

```ts
const href = router.href('users.details', {
  params: {
    id: 42,
  },
  search: {
    tab: 'activity',
  },
  hash: 'profile',
});
```

Object form:

```ts
const href = router.href({
  route: 'users.details',
  params: {
    id: 42,
  },
});
```

`href()` validates required params and path constraints while building.

Missing required param throws:

```text
Route "users.details" expected param "id" for path token "{id:int}".
```

Unknown route IDs throw the unknown-route diagnostic.

`href()` builds only. It does not run middleware, lifecycle, blockers, redirects, or preload work.

## `router.resolve()`

```ts
router.resolve(routeId, options?)
router.resolve(options)
```

Builds an href for a route ID and then matches it back against the router.

```ts
const match = router.resolve('users.details', {
  params: {
    id: 42,
  },
});
```

Use `resolve()` when a custom integration needs the full parsed match state for a generated route target.

If the generated href does not resolve back to a match, it throws:

```text
Resolved route "users.details" did not match its generated href.
```

`resolve()` is stricter than `href()`. It proves the generated URL is matchable by the current router.

## `router.match()`

```ts
router.match(
  href: string,
  options?: MatchOptions,
): RegisteredRouteMatch | null;
```

Matches an arbitrary href against the router.

```ts
const match = router.match(
  '/users/42?tab=settings#profile',
);
```

No match returns `null`.

```ts
router.match('/missing');
// null
```

`match()` parses path params, declared search, preserved unknown search, and hash state according to the effective URL policy.

Use the `url` option for per-call matching policy:

```ts
router.match('/products?tags=router,typescript', {
  url: {
    arrayFormat: 'comma',
  },
});
```

## `router.preload()`

```ts
router.preload(routeId, options?)
router.preload(options)
```

Preloads a route target without committing navigation.

```ts
await router.preload('users.details', {
  params: {
    id: 42,
  },
});
```

With abort signal:

```ts
const controller = new AbortController();

void router.preload('users.details', {
  params: {
    id: 42,
  },
  signal: controller.signal,
});

controller.abort();
```

For each route in the matched branch, preloading runs in order:

1. `modulePreload`;
2. layout view `preload`;
3. route view `preload`;
4. declared route `preload`.

It does not run:

* blockers;
* middleware;
* lifecycle hooks;
* redirects;
* rewrites;
* history mutations.

Unsignaled concurrent calls share work by href and URL policy. Signaled calls remain independently cancellable.

Unknown targets can throw before a promise is returned.

## `router.preloadHref()`

```ts
router.preloadHref(
  href: string,
  options?: PreloadHrefOptions,
): Promise<void>;
```

Preloads an arbitrary app href after matching it.

```ts
await router.preloadHref(
  '/users/42?tab=settings#profile',
);
```

With per-call URL policy:

```ts
await router.preloadHref('/products?tags=a,b', {
  url: {
    arrayFormat: 'comma',
  },
});
```

With abort signal:

```ts
const controller = new AbortController();

await router.preloadHref('/users/42', {
  signal: controller.signal,
});
```

If the href does not match a route, it throws the unknown-route diagnostic.

## `router.navigate.to()`

```ts
router.navigate.to(href, options?)
router.navigate.to(routeId, options?)
router.navigate.to(options)
```

Pushes a new history entry and resolves a transition.

Route-ID navigation:

```ts
await router.navigate.to('users.details', {
  params: {
    id: 42,
  },
  search: {
    tab: 'activity',
  },
});
```

Object-form navigation:

```ts
await router.navigate.to({
  route: 'users.details',
  params: {
    id: 42,
  },
});
```

Literal href navigation:

```ts
await router.navigate.to(
  '/users/42?tab=activity#profile',
);
```

Literal hrefs must be app-internal hrefs.

Allowed:

```ts
'/users/42'
'/users/42?tab=activity'
'/users/42#profile'
```

Rejected:

```ts
'users.details'
'https://example.com/users/42'
'//example.com/users/42'
```

A literal href is not a route ID. Route-build options are invalid with literal href navigation.

Wrong:

```ts
await router.navigate.to('/users/42', {
  search: {
    tab: 'activity',
  },
});
```

Error:

```text
Cannot navigate to internal href "/users/42" with route option "search". Pass params, search, and hash in the href string instead.
```

Valid literal href:

```ts
await router.navigate.to(
  '/users/42?tab=activity',
);
```

## `router.navigate.replace()`

```ts
router.navigate.replace(href, options?)
router.navigate.replace(routeId, options?)
router.navigate.replace(options)
```

Replaces the current history entry and resolves a transition.

```ts
await router.navigate.replace('login', {
  search: {
    redirect: '/dashboard',
  },
});
```

Literal href replacement:

```ts
await router.navigate.replace('/login?redirect=%2Fdashboard');
```

The same literal-href restrictions from `navigate.to()` apply.

## Interception and scroll metadata

Route-ID and object navigation can carry interception and scroll metadata.

```ts
await router.navigate.to('documents.details', {
  params: {
    documentId,
  },
  intercept: {
    slot: 'modal',
    view: DocumentPreview,
  },
  context: {
    source: 'documents-list',
  },
  preventScrollReset: true,
});
```

`intercept: false` disables configured interception for that navigation.

```ts
await router.navigate.replace(redirectTo, {
  intercept: false,
});
```

`preventScrollReset` is stored in history state. The core router never scrolls the document. Rendering integrations, such as React provider scroll restoration, may read the flag.

## `router.navigate.back()`, `forward()`, and `go(delta)`

```ts
router.navigate.back(): void;
router.navigate.forward(): void;
router.navigate.go(delta: number): void;
```

Delegates to the underlying history adapter.

```ts
router.navigate.back();
router.navigate.forward();
router.navigate.go(-2);
```

These methods do not return a transition promise. Listen through `subscribe()` or wait for your rendering integration to observe the state update.

## `router.subscribe(listener)`

```ts
router.subscribe(
  listener: (state: RouterState) => void,
): () => void;
```

Subscribes to router state changes.

```ts
const unsubscribe = router.subscribe((state) => {
  console.log(state.navigation, state.location.href);
});

unsubscribe();
```

After disposal, `subscribe()` returns a no-op cleanup function.

It does not throw.

## `router.block(blocker)`

```ts
interface RouterBlockerContext {
  readonly from: RouteMatch | null;
  readonly to: RouteMatch | null;
  readonly location: RouterLocation;
}

type RouterBlocker = (
  context: RouterBlockerContext,
) => boolean | void | Promise<boolean | void>;

router.block(blocker: RouterBlocker): () => void;
```

Registers a navigation blocker.

<TypeTable
  type={{
    from: {
      description: 'Current match before the attempted transition.',
      type: 'RouteMatch | null',
    },
    to: {
      description: 'Target match for the attempted transition.',
      type: 'RouteMatch | null',
    },
    location: {
      description: 'Target router location.',
      type: 'RouterLocation',
    },
  }}
/>

Return `false` to block the transition.

```ts
const unblock = router.block(({ to }) => {
  if (formIsDirty && to?.id !== 'messages.new') {
    return false;
  }
});

unblock();
```

Throwing from a blocker places the attempted transition into error state.

Blockers run before middleware and lifecycle hooks.

## `router.useMiddleware(middleware)`

```ts
router.useMiddleware(
  middleware: readonly Middleware[],
): () => void;
```

Registers runtime middleware for as long as the cleanup is retained.

```ts
const cleanup = router.useMiddleware([
  ({ route, redirect }) => {
    if (route.route.meta?.access === 'private') {
      return redirect('/login');
    }
  },
]);

cleanup();
```

Runtime middleware participates in future transitions.

If middleware must affect initial startup, register it before `start()`.

```ts
router.useMiddleware([authMiddleware]);

await router.start();
```

Or pass it during router creation:

```ts
const router = createRouter({
  routes,
  middleware: [authMiddleware],
});
```

## `router.start()`

```ts
router.start(): Promise<RouterState>;
```

Resolves the current history or static location through canonicalization, route redirects, blockers, middleware, lifecycle hooks, and route matching.

```ts
await router.start();
```

Concurrent calls share one in-flight startup promise.

After startup has completed, repeated calls return the current state and do not re-run navigation work.

```ts
await Promise.all([
  router.start(),
  router.start(),
]);
```

Use `start()` before SSR rendering with `StaticRouterProvider`.

## `router.refresh()`

```ts
router.refresh(): Promise<RouterState>;
```

Re-resolves the current history or static location without pushing history.

```ts
await router.refresh();
```

Use it to:

* retry the current route;
* re-run current-location middleware and lifecycle hooks;
* recover from browser-only hash hydration after React has committed;
* refresh route state after external auth or cache changes.

`refresh()` does not push a new history entry.

## `router.serialize()`

```ts
router.serialize(): SerializedRouterState;
```

Returns the minimal hydration state.

```ts
const state = router.serialize();
```

The serialized shape is:

```ts
interface SerializedRouterState {
  readonly location: RouterLocation;
  readonly navigation: RouterNavigationState;
}
```

`error` is not serialized.

`match` is not serialized.

The client reconstructs route matching from the serialized location and its own route tree.

## `router.dispose()`

```ts
router.dispose(): void;
```

Disposes the router runtime.

It:

* marks the router as disposed;
* stops the history listener;
* clears active startup state;
* invalidates in-flight transitions;
* clears active preload sharing;
* clears runtime middleware;
* clears blockers;
* clears subscribers.

```ts
router.dispose();
```

Disposal is idempotent.

```ts
router.dispose();
router.dispose();
```

After disposal, these methods throw synchronously:

```text
start()
refresh()
preload()
preloadHref()
navigate.to()
navigate.replace()
navigate.back()
navigate.forward()
navigate.go()
block()
useMiddleware()
```

Error:

```text
Router has been disposed. Create a new router instance before starting, navigating, refreshing, or preloading.
```

`subscribe()` does not throw after disposal. It returns a no-op cleanup function.

These read/build operations do not currently assert disposal:

```text
href()
resolve()
match()
serialize()
```

Do not treat that as permission to keep using a disposed router as application state. Create a new router instance.

## Preloading order

Route preloading runs against the matched branch from root to leaf.

For each branch route, it runs:

1. `route.route.modulePreload`;
2. `route.layout?.view.preload`;
3. `route.view.preload`;
4. `route.route.preload(context)`.

```ts
{
  id: 'users.details',
  path: '/users/{id:int}',
  preload: async ({ params, signal }) => {
    await queryClient.prefetchQuery({
      queryKey: ['user', params.id],
      queryFn: () =>
        fetchUser(params.id, { signal }),
    });
  },
}
```

The preload context includes parsed params, search, unknown search, hash, current location, the matched route, the full match, and an `AbortSignal`.

Preloading is warming. It is not navigation.

## Redirects, rewrites, and external destinations

Route redirects and middleware redirects participate in transitions.

Redirect loops stop at `maxRedirectDepth`.

Error:

```text
Navigation exceeded the maximum redirect count.
```

External redirects require history support.

If the history implementation cannot redirect externally, the router enters error state.

```text
History implementation cannot redirect to external URL "https://example.com".
```

Middleware rewrites cannot target external URLs.

```text
Middleware cannot rewrite to external URL "https://example.com".
```

An app-internal navigation href must begin with `/` and must not begin with `//`.

External destinations belong to native browser navigation or an environment-supported redirect response, not `router.navigate.to()`.

Merge modes:

| Mode        | Behavior                                                                        |
| ----------- | ------------------------------------------------------------------------------- |
| `'leaf'`    | Leaf value wins.                                                                |
| `'shallow'` | Plain objects are shallow-merged; other values are replaced by leaf values.     |
| `'deep'`    | Plain objects are recursively merged; other values are replaced by leaf values. |
| `'append'`  | Values are coerced to arrays and appended root-to-leaf.                         |
| `'prepend'` | Values are coerced to arrays and prepended leaf-to-root.                        |

```ts
  getActiveRouteMetaChain(router.state.match, {
    includeAncestors: true,
  }),
  {
    default: 'shallow',
    keys: {
      breadcrumbs: 'append',
    },
  },
);
```

`undefined` metadata values are skipped while merging.

```text
>

U+2029
```

```ts
const serialized = stringifyRouterState(router);
```

```ts

  state: SerializedRouterState | string,
```


Invalid serialized state throws during deserialization instead of letting the router hydrate from a malformed object.

## SSR and hydration behavior

Server rendering:

```ts
const router = createStaticRouter({
  routes,
  request,
});

await router.start();

const hydrationData = stringifyRouterState(router);
```

Client hydration:

```ts
const router = createRouter({
  routes,
  hydrationData: deserializeRouterState(
    window.__COOKBOOK_ROUTER__,
  ),
});
```

Hydration data must match the client history pathname and search string.

Hash fragments are client-only for direct HTTP requests. A browser may have a hash the server never saw. The router keeps the serialized server location for initial hydration; rendering integrations can refresh after commit to reconcile the browser hash.

## Where this bites

### Initial state is not the same as startup

Router creation computes state for the current location.

`start()` still matters.

```ts
const router = createMemoryRouter({
  routes,
  initialEntries: ['/private'],
});

router.state.match?.id;
// may already be 'private'

await router.start();
// middleware, redirects, rewrites, and lifecycle now run
```

Do not skip `start()` when initial route guards must run.

### Literal href navigation is not route building

This is wrong:

```ts
await router.navigate.to('/users/42', {
  search: {
    tab: 'activity',
  },
});
```

Literal hrefs already contain their search and hash.

Use a route ID:

```ts
await router.navigate.to('users.details', {
  params: {
    id: 42,
  },
  search: {
    tab: 'activity',
  },
});
```

or put the search in the href:

```ts
await router.navigate.to(
  '/users/42?tab=activity',
);
```

### External destinations are not router navigation targets

This is wrong:

```ts
await router.navigate.to(
  'https://example.com',
);
```

Router navigation is for app-internal hrefs and route IDs.

Use native browser navigation, an anchor, or an environment-supported redirect response.

### Provider middleware after startup misses the first route

This is too late for initial navigation:

```ts
await router.start();

router.useMiddleware([authMiddleware]);
```

Use:

```ts
router.useMiddleware([authMiddleware]);

await router.start();
```

or pass middleware to router creation.

### `preload()` is not navigation

This warms route work:

```ts
await router.preload('users.details', {
  params: {
    id: 42,
  },
});
```

It does not change history, run blockers, run middleware, or commit a route.

### Disposed routers are dead application state

This throws:

```ts
router.dispose();

await router.navigate.to('/users/42');
```

This may still build a string:

```ts
router.href('users.details', {
  params: {
    id: 42,
  },
});
```

Do not keep using a disposed router because one read/build method still returns a value. Create a new router instance.
