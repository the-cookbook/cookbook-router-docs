The `@cookbook/router/path` entrypoint exposes Router path analysis, slash-pruning utilities, path-match option contracts, and custom path constraint registration.

Cookbook Router delegates route-pattern grammar, path compilation, and param matching to URLKit. The Router package exposes only the stable path API needed by route declarations, router creation, tests, diagnostics, and generated integrations.

```ts ts2js
import {
  analyzePathPattern,
  createPathConstraint,
  getPathConstraint,
  hasPathConstraint,
  normalizePathOptions,
  prunePathname,
  registerPathConstraints,
  resetPathConstraints,
  unregisterPathConstraint,
} from '@cookbook/router/path';

import type {
  AnalyzedPathPattern,
  PathPruneOption,
  RouterPathConstraint,
  RouterPathConstraints,
  RouterPathMatchOptions,
  RouterPathOptions,
} from '@cookbook/router/path';
```

The package root re-exports the common path constraint helpers and router path option types:

```ts ts2js
import {
  createPathConstraint,
  getPathConstraint,
  hasPathConstraint,
  registerPathConstraints,
  unregisterPathConstraint,
} from '@cookbook/router';

import type {
  RouterPathConstraint,
  RouterPathConstraints,
  RouterPathMatchOptions,
  RouterPathOptions,
} from '@cookbook/router';
```

The root does not re-export every path subpath helper. Use `@cookbook/router/path` for path-specific utilities such as `analyzePathPattern()`, `normalizePathOptions()`, `prunePathname()`, `resetPathConstraints()`, and `PathPruneOption`.

For route-authoring syntax and examples, see [Path routes and constraints](/docs/router/concepts/path-routes-and-constraints).

## `PathPruneOption`

```ts ts2js
type PathPruneOption =
  | 'all'
  | 'duplication'
  | 'trailing'
  | false;
```

Controls slash normalization.

| Value           | Behavior                                 | `/users//42/` becomes |
| --------------- | ---------------------------------------- | --------------------- |
| `'all'`         | Remove duplicate and trailing slashes.   | `/users/42`           |
| `'duplication'` | Remove duplicate slashes only.           | `/users/42/`          |
| `'trailing'`    | Remove trailing slashes only.            | `/users//42`          |
| `false`         | Preserve duplicate and trailing slashes. | `/users//42/`         |

## `RouterPathOptions`

```ts ts2js
interface RouterPathOptions {
  readonly prune?: PathPruneOption;
}
```

<TypeTable
  type={{
    prune: {
      description: 'Slash-pruning mode used during validation, normalization, matching, href generation, and canonicalization.',
      type: "PathPruneOption",
      default: "'all'",
      optional: true,
    },
  }}
/>

`RouterPathOptions` can be supplied while defining routes:

```ts ts2js
import { defineRoutes } from '@cookbook/router/route-config';

export const routes = defineRoutes(
  [
    {
      id: 'users.details',
      path: '/users//{id:int}/',
    },
  ] as const,
  {
    pathOptions: {
      prune: 'all',
    },
  },
);
```

It can also be supplied while creating a router:

```ts ts2js
import { createRouter } from '@cookbook/router/runtime';

export const router = createRouter({
  routes,
  pathOptions: {
    prune: 'all',
  },
});
```

Route-declaration options apply while paths are validated and normalized. Router options apply when the router receives raw route arrays and when runtime APIs build or match paths. Keep them consistent when declarations and runtime creation live in different modules.

DEFAULT_PATH_OPTIONS.prune;

## `normalizePathOptions(options?)`

```ts ts2js
function normalizePathOptions(
  options?: RouterPathOptions,
): Required<RouterPathOptions>;
```

Fills omitted path options with Router defaults.

```ts ts2js
import { normalizePathOptions } from '@cookbook/router/path';

normalizePathOptions();
// { prune: 'all' }

normalizePathOptions({ prune: false });
// { prune: false }
```

Use this in diagnostics, adapters, and tests that need to show the effective path policy.

## `prunePathname(pathname, options?)`

```ts ts2js
function prunePathname(
  pathname: string,
  options?: RouterPathOptions,
): string;
```

Applies slash pruning to a pathname.

```ts ts2js
import { prunePathname } from '@cookbook/router/path';

prunePathname('/users//42/');
// '/users/42'

prunePathname('/users//42/', {
  prune: 'duplication',
});
// '/users/42/'

prunePathname('/users//42/', {
  prune: 'trailing',
});
// '/users//42'

prunePathname('/users//42/', {
  prune: false,
});
// '/users//42/'
```

Empty input normalizes to root:

```ts ts2js
prunePathname('');
// '/'
```

The root path stays stable:

```ts ts2js
prunePathname('/');
// '/'
```

This helper only prunes slashes. It does not parse route patterns, validate params, decode segments, or match routes.

## `RouterPathMatchOptions`

```ts ts2js
interface RouterPathMatchOptions {
  readonly trailing?: boolean;
  readonly strict?: boolean;
  readonly sensitive?: boolean;
  readonly end?: boolean;
  readonly wildcardFormat?: 'string' | 'array';
  readonly decode?: boolean | ((value: string) => string);
}
```

These options configure serialized pathname matching through `RouterUrlOptions.pathMatch`.

<TypeTable
  type={{
    trailing: {
      description: 'Allows one final delimiter while matching.',
      type: 'boolean',
      optional: true,
    },
    strict: {
      description: 'Surfaces constraint failures instead of treating them as ordinary route misses.',
      type: 'boolean',
      optional: true,
    },
    sensitive: {
      description: 'Enables case-sensitive path matching.',
      type: 'boolean',

    },
    end: {
      description: 'Controls whether matching must consume the complete pathname. Mostly useful for prefix-routing integrations.',
      type: 'boolean',
      optional: true,
    },
    wildcardFormat: {
      description: 'Controls wildcard capture representation before Router-normalized params are exposed.',
      type: "'string' | 'array'",
      optional: true,
    },
    decode: {
      description: 'Enables standard decoding, disables decoding, or supplies a custom segment decoder.',
      type: 'boolean | ((value: string) => string)',
      optional: true,
    },
  }}
/>

Router-level matching policy:

```ts ts2js
import { createRouter } from '@cookbook/router/runtime';

const router = createRouter({
  routes,
  url: {
    pathMatch: {
      sensitive: true,
      strict: true,
    },
  },
});
```

Per-call matching policy:

```ts ts2js
const match = router.match('/Files/README', {
  url: {
    pathMatch: {
      sensitive: true,
    },
  },
});
```

`pathMatch` is a matching policy. Href build APIs do not use match-only options.

## `analyzePathPattern(pattern)`

```ts ts2js
interface AnalyzedPathPattern {
  readonly params: readonly RouteParamDefinition[];
  readonly score: number;
  readonly depth: number;
}

function analyzePathPattern(
  pattern: string,
): AnalyzedPathPattern;
```

Analyzes a PathKit route pattern and returns Router metadata used by normalization and ranking.

<TypeTable
  type={{
    params: {
      description: 'Param definitions discovered in the pattern.',
      type: 'readonly RouteParamDefinition[]',
    },
    score: {
      description: 'Specificity score used by route ranking. Literal segments score highest, params next, wildcards lowest.',
      type: 'number',
    },
    depth: {
      description: 'Segment depth of the parsed pattern.',
      type: 'number',
    },
  }}
/>

Root pattern:

```ts ts2js
analyzePathPattern('/');
// {
//   params: [],
//   score: 0,
//   depth: 0,
// }
```

Literal segments:

```ts ts2js
analyzePathPattern('/users/settings');
// {
//   params: [],
//   score: 10,
//   depth: 2,
// }
```

Params, constraints, and wildcards:

```ts ts2js
analyzePathPattern(
  '/files/{type:list(image|video)}/{*path?}',
);
```

Result shape:

```ts ts2js
{
  score: 9,
  depth: 3,
  params: [
    {
      name: 'type',
      constraints: [
        {
          type: 'list',
          params: 'image|video',
        },
      ],
      wildcard: false,
      optional: false,
      token: '{type:list(image|video)}',
    },
    {
      name: 'path',
      constraints: [],
      wildcard: true,
      optional: true,
      token: '{*path?}',
    },
  ],
}
```

The returned analysis object, `params` array, param entries, constraint arrays, and constraint entries are frozen.

`analyzePathPattern()` is a diagnostic and integration helper. It is not a replacement for route-tree validation.

## Constraint contracts

```ts ts2js
type RouterPathConstraint = ConstraintValidation;

type RouterPathConstraints = Readonly<
  Record<string, RouterPathConstraint>
>;
```

`RouterPathConstraint` is URLKit’s path constraint validation contract.

A custom constraint normally provides:

```ts ts2js
interface ConstraintValidation {
  readonly parse: (
    paramName: string,
    value: string | number | boolean | undefined,
    params: string,
  ) => void;

  readonly verify: (
    paramName: string,
    params: string,
  ) => void;

  readonly toRegExp?: (
    params: string,
  ) => string;
}
```

<TypeTable
  type={{
    parse: {
      description: 'Validates a matched or generated param value. Throw to reject the value.',
      type: '(paramName: string, value: string | number | boolean | undefined, params: string) => void',
    },
    verify: {
      description: 'Validates constraint arguments from the route pattern. Throw to reject the declaration.',
      type: '(paramName: string, params: string) => void',
    },
    toRegExp: {
      description: 'Returns regex source text for segment matching when the constraint needs custom syntax.',
      type: '(params: string) => string',
      optional: true,
    },
  }}
/>

The regex return value is source text, not a JavaScript regex literal.

Correct:

```ts ts2js
return '[a-z0-9-]+';
```

Wrong:

```ts ts2js
return '/[a-z0-9-]+/';
```

## `createPathConstraint(definition)`

```ts ts2js
function createPathConstraint(
  definition: ConstraintValidation,
): RouterPathConstraint;
```

Creates a URLKit-compatible path constraint.

```ts ts2js
import {
  createPathConstraint,
} from '@cookbook/router/path';

export const slug = createPathConstraint({
  parse(paramName, value) {
    if (
      typeof value !== 'string' ||
      !/^[a-z0-9-]+$/.test(value)
    ) {
      throw new Error(
        `Parameter "${paramName}" must be a valid slug.`,
      );
    }
  },

  verify(_paramName, params) {
    if (params) {
      throw new Error('slug does not accept parameters.');
    }
  },

  toRegExp() {
    return '[a-z0-9-]+';
  },
});
```

Use the constraint in route options:

```ts ts2js
import { defineRoutes } from '@cookbook/router/route-config';

export const routes = defineRoutes(
  [
    {
      id: 'posts.show',
      path: '/posts/{slug:slug}',
    },
  ] as const,
  {
    pathConstraints: {
      slug,
    },
  },
);
```

Custom constraints remain `string` in generated contracts unless combined with a numeric built-in constraint.

## `registerPathConstraints(constraints?)`

```ts ts2js
function registerPathConstraints(
  constraints?: RouterPathConstraints,
): void;
```

Registers custom constraints with URLKit’s process-level path registry.

```ts ts2js
import { registerPathConstraints } from '@cookbook/router/path';

registerPathConstraints({
  slug,
});
```

Behavior:

* `undefined` is a no-op;
* passing the same constraint object reference again is a no-op;
* registration is process-global;
* existing names are overwritten for contracts created or activated afterwards;
* empty or whitespace-only names throw.

Empty-name diagnostic:

```text
Path constraint name must be a non-empty string.
```

`registerPathConstraints()` does not retroactively rewrite already-normalized route metadata. Register constraints before validation, router creation, matching, href generation, or CLI route loading.

Preferred route-authoring pattern:

```ts ts2js
export const routes = defineRoutes(
  [
    {
      id: 'posts.show',
      path: '/posts/{slug:slug}',
    },
  ] as const,
  {
    pathConstraints: {
      slug,
    },
  },
);
```

`defineRoutes()` validates immediately. Supplying the constraint later only to `createRouter()` is too late for that already-executed validation call.

Use router-level `pathConstraints` only when the router receives raw route arrays that were not already validated by `defineRoutes()` or `defineRouteTree()`:

```ts ts2js
const router = createRouter({
  routes: [
    {
      id: 'posts.show',
      path: '/posts/{slug:slug}',
    },
  ],
  pathConstraints: {
    slug,
  },
});
```

## `hasPathConstraint(name)`

```ts ts2js
function hasPathConstraint(
  name: string,
): boolean;
```

Reports whether URLKit’s process-level path registry currently contains the name.

```ts ts2js
hasPathConstraint('slug');
// true
```

Use it for diagnostics and test setup. It does not prove that every environment registered the same implementation.

## `getPathConstraint(name)`

```ts ts2js
function getPathConstraint(
  name: string,
): RouterPathConstraint | undefined;
```

Returns the registered constraint object when available.

```ts ts2js
const constraint = getPathConstraint('slug');

if (!constraint) {
  throw new Error('slug constraint was not registered.');
}
```

Treat the returned object as registry state, not as route-local configuration.

## `unregisterPathConstraint(name)`

```ts ts2js
function unregisterPathConstraint(
  name: string,
): void;
```

Removes one constraint from URLKit’s process-level registry.

```ts ts2js
unregisterPathConstraint('slug');
```

This is mainly for test isolation. Avoid dynamically swapping application constraints after route creation.

The wrapper also clears Router’s active constraint reference, so a later `registerPathConstraints()` call with the same object can register again.

## `resetPathConstraints()`

```ts ts2js
function resetPathConstraints(): void;
```

Clears Router’s active constraint reference and resets URLKit’s process-level path constraint registry.

```ts ts2js
import { resetPathConstraints } from '@cookbook/router/path';

afterEach(() => {
  resetPathConstraints();
});
```

This helper is exported from `@cookbook/router/path`. It is not re-exported by the root package.

Use it in tests that register custom constraints. Do not call it in application runtime unless you are intentionally tearing down a router test environment.

## Built-in constraint grammar

| Constraint    | Pattern                    | Resolved Router type |
| ------------- | -------------------------- | -------------------- |
| unconstrained | `{slug}`                   | `string`             |
| `int`         | `{id:int}`                 | `number`             |
| `decimal`     | `{price:decimal}`          | `number`             |
| `uuid`        | `{id:uuid}`                | `string`             |
| `min`         | `{price:min(1)}`           | `number`             |
| `max`         | `{price:max(10)}`          | `number`             |
| `range`       | `{page:range(1,100)}`      | `number`             |
| `minlength`   | `{slug:minlength(3)}`      | `string`             |
| `maxlength`   | `{slug:maxlength(50)}`     | `string`             |
| `list`        | `{view:list(grid\|list)}`  | `string`             |
| `regex`       | `{slug:regex([a-z0-9-]+)}` | `string`             |
| wildcard      | `{*path}`                  | `readonly string[]`  |

A numeric built-in anywhere in the constraint chain makes the resolved Router param a number.

```ts ts2js
{
  id: 'products.page',
  path: '/products/{page:int}',
}
```

The resolved param is:

```ts ts2js
{
  page: number;
}
```

Arbitrary custom constraints remain `string` in generated contracts unless they are combined with a numeric built-in.

```ts ts2js
{
  id: 'posts.show',
  path: '/posts/{slug:slug}',
}
```

The resolved param is:

```ts ts2js
{
  slug: string;
}
```

Wildcard params resolve to arrays:

```ts ts2js
{
  id: 'files',
  path: '/files/{*path}',
}
```

The resolved param is:

```ts ts2js
{
  path: readonly string[];
}
```

## Environment consistency

Custom constraints are executable configuration.

Every environment that validates, matches, or builds paths must load the same names before using routes:

* browser;
* server;
* tests;
* CLI route loading;
* build plugins;
* static generation;
* SSR request handlers.

A generated contract can describe `{slug:slug}`, but it cannot carry the JavaScript implementation of `slug` into another process.

Keep constraint definitions in one module and import them wherever route loading happens.

```ts ts2js
// path-constraints.ts
import { createPathConstraint } from '@cookbook/router/path';

export const pathConstraints = {
  slug: createPathConstraint({
    parse(paramName, value) {
      if (
        typeof value !== 'string' ||
        !/^[a-z0-9-]+$/.test(value)
      ) {
        throw new Error(
          `Parameter "${paramName}" must be a valid slug.`,
        );
      }
    },
    verify() {},
    toRegExp: () => '[a-z0-9-]+',
  }),
};
```

Use that same object in route loading:

```ts ts2js
defineRoutes(routes, {
  pathConstraints,
});
```

and in config/build tooling when routes are loaded outside the app process.

## Where this bites

### The path subpath is public

This is valid:

```ts ts2js
import {
  createPathConstraint,
  prunePathname,
} from '@cookbook/router/path';
```

The old “root-only” wording is wrong for the current package.

### Registration after validation is too late

This validates immediately:

```ts ts2js
const routes = defineRoutes([
  {
    id: 'posts.show',
    path: '/posts/{slug:slug}',
  },
] as const);
```

Registering `slug` later cannot make that earlier validation succeed.

Pass constraints into `defineRoutes()` or `defineRouteTree()`:

```ts ts2js
const routes = defineRoutes(routeDefinitions, {
  pathConstraints: {
    slug,
  },
});
```

### Registry state is process-global

This is fine in a single test:

```ts ts2js
registerPathConstraints({ slug });
```

It is risky across a large test suite unless you reset:

```ts ts2js
afterEach(() => {
  resetPathConstraints();
});
```

### Regex source is not a regex literal

Correct:

```ts ts2js
toRegExp() {
  return '[a-z0-9-]+';
}
```

Wrong:

```ts ts2js
toRegExp() {
  return '/[a-z0-9-]+/';
}
```

PathKit expects source text.

### `prunePathname()` is not matching

This only normalizes slashes:

```ts ts2js
prunePathname('/users//42/');
```

It does not verify that `/users/42` matches any route, and it does not parse `{id:int}`.

Use `matchRoutes()` or `router.match()` for matching.
