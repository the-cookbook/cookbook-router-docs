The `@cookbook/router/route-config` entrypoint owns authored route shapes, modular route composition, tree validation, and normalized route contracts.

It is the route authoring surface. It is not the runtime navigation API.

```ts ts2js
import {
  defineRoute,
  defineRouteTree,
  defineRoutes,
  normalizeRoutes,
  validateResolvedRouteTree,
  validateRoutes,
} from '@cookbook/router/route-config';

import type {
  DefineRouteTreeOptions,
  DefineRoutesOptions,
  RouteDeclaration,
  RouteDefinition,
  RouteLayoutDefinition,
  RouteSlotConfig,
  RouteSlotDefinition,
  RouteInterceptConfig,
  RouteIntercepts,
  RouteRedirect,
  RouteSearchSchema,
  RouteHashSchema,
  RoutePreload,
  RoutePreloadContext,
  RouteLifecycle,
  Middleware,
  NormalizedRoute,
  RouteMatch,
  MatchedRoute,
} from '@cookbook/router/route-config';
```

Descriptor helpers such as `defineSearch()`, `mergeSearch()`, and `defineHash()` are related to route configuration, but they are root exports:

```ts ts2js
import {
  defineHash,
  defineSearch,
  mergeSearch,
} from '@cookbook/router';
```

Do not import them from `@cookbook/router/route-config`.

## `defineRoute(route)`

```ts ts2js
function defineRoute<
  const Route extends RouteDeclaration,
>(route: Route): Route;
```

Preserves literal fields in one modular route declaration.

It does not validate the graph, attach the route to a parent, sort siblings, or strip composition-only fields. It returns the object you passed in.

```ts ts2js
import { defineRoute } from '@cookbook/router/route-config';

export const usersRoute = defineRoute({
  id: 'users',
  path: '/users',
} as const);

export const userDetailsRoute = defineRoute({
  id: 'users.details',
  parent: 'users',
  path: '{slug:slug}',
  order: 10,
} as const);
```

Use it for split route modules that are composed later with `defineRouteTree()` or by the CLI.

`parent` names another route ID. `order` is a modular-composition hint only.

## `defineRouteTree(options)`

```ts ts2js
interface DefineRouteTreeOptions {
  readonly routes: readonly RouteDeclaration[];
  readonly pathOptions?: RouterPathOptions;
  readonly pathConstraints?: RouterPathConstraints;
}

function defineRouteTree<
  const Routes extends readonly RouteDeclaration[],
>(
  options: DefineRouteTreeOptions & {
    readonly routes: Routes;
  },
): readonly RouteDefinition[];
```

Composes modular route declarations into runtime `RouteDefinition[]`.

It:

* registers supplied custom path constraints;
* collects inline and parent-attached declarations;
* validates parent relationships;
* rejects cycles;
* rejects duplicate route IDs;
* rejects absolute paths on parent-attached child declarations;
* rejects children under redirect routes;
* validates configured intercept targets and slots;
* sorts siblings deterministically;
* validates the final route tree;
* strips `parent` and `order` from returned runtime routes;
* stores `pathOptions` and `pathConstraints` on the returned array for router creation and generation.

```ts ts2js
import {
  defineRoute,
  defineRouteTree,
} from '@cookbook/router/route-config';

const rootRoute = defineRoute({
  id: 'root',
  path: '/',
  layout: {
    view: RootLayout,
    slots: {
      modal: true,
    },
  },
} as const);

const overviewRoute = defineRoute({
  id: 'overview',
  parent: 'root',
  path: 'overview',
  order: 10,
} as const);

const createRoute = defineRoute({
  id: 'create',
  parent: 'root',
  path: 'create',
} as const);

export const routes = defineRouteTree({
  routes: [
    rootRoute,
    overviewRoute,
    createRoute,
  ],
});
```

With custom constraints:

```ts ts2js
import { createPathConstraint } from '@cookbook/router/path';
import { defineRouteTree } from '@cookbook/router/route-config';

const slug = createPathConstraint({
  parse: (paramName, value) => {
    if (!/^[a-z0-9-]+$/.test(value)) {
      throw new Error(
        `Parameter "${paramName}" must be a slug.`,
      );
    }
  },
  verify: (_paramName, params) => {
    if (params) {
      throw new Error('slug does not accept parameters.');
    }
  },
  toRegExp: () => '[a-z0-9-]+',
});

export const routes = defineRouteTree({
  routes: [
    {
      id: 'post',
      path: '/posts/{slug:slug}',
    },
  ],
  pathConstraints: {
    slug,
  },
});
```

### Sibling sorting

`defineRouteTree()` sorts siblings by:

1. `order`, ascending;
2. index routes before non-index routes when order ties;
3. path specificity, descending;
4. declaration order.

```ts ts2js
const routes = defineRouteTree({
  routes: [
    defineRoute({
      id: 'dashboard',
      path: '/dashboard',
      children: [
        defineRoute({
          id: 'dashboard.index',
          index: true,
        } as const),
        defineRoute({
          id: 'dashboard.settings',
          path: 'settings',
          order: 20,
        } as const),
      ],
    } as const),
    defineRoute({
      id: 'dashboard.users',
      parent: 'dashboard',
      path: 'users',
      order: 10,
    } as const),
  ],
} as const);
```

The child order is:

```text
dashboard.users
dashboard.settings
dashboard.index
```

Order wins first. Index priority is not magic enough to beat an explicit lower `order`.

## `defineRoutes(routes, options?)`

```ts ts2js
interface DefineRoutesOptions {
  readonly pathOptions?: RouterPathOptions;
  readonly pathConstraints?: RouterPathConstraints;
}

function defineRoutes<
  const Routes extends readonly RouteDefinition[],
>(
  routes: Routes,
  options?: DefineRoutesOptions,
): Routes;
```

Validates one already-nested route tree immediately and preserves its literal type.

It also registers custom path constraints before validation and stores route options on the returned array with a non-enumerable shared symbol.

```ts ts2js
import { defineRoutes } from '@cookbook/router/route-config';

export const routes = defineRoutes([
  {
    id: 'root',
    path: '/',
    children: [
      {
        id: 'home',
        index: true,
      },
      {
        id: 'users.details',
        path: 'users/{id:int}',
        hash: {
          type: 'enum',
          values: ['profile', 'settings'],
          optional: true,
        },
      },
    ],
  },
] as const);
```

With path options:

```ts ts2js
export const routes = defineRoutes(
  [
    {
      id: 'gallery',
      path: '/gallery/',
    },
  ] as const,
  {
    pathOptions: {
      prune: false,
    },
  },
);
```

## Descriptor helpers

These helpers preserve literal static URL descriptors for inference and CLI extraction.

They are exported from `@cookbook/router`, not `@cookbook/router/route-config`.

```ts ts2js
function defineSearch<
  const Search extends RouteSearchSchema,
>(search: Search): Search;

function mergeSearch<
  const Descriptors extends readonly RouteSearchSchema[],
>(
  ...descriptors: Descriptors
): MergedSearchDescriptors<Descriptors>;

function defineHash<
  const Hash extends RouteHashSchema,
>(hash: Hash): Hash;
```

```ts ts2js
import {
  defineHash,
  defineSearch,
  mergeSearch,
} from '@cookbook/router';

const paginationSearch = defineSearch({
  page: {
    type: 'int',
    default: 1,
  },
} as const);

const usersSearch = defineSearch({
  q: {
    type: 'string',
    optional: true,
  },
  status: {
    type: 'enum',
    values: ['all', 'active', 'disabled'],
    default: 'all',
  },
} as const);

const userHash = defineHash({
  type: 'enum',
  values: ['profile', 'settings'],
  optional: true,
} as const);

export const routes = defineRoutes([
  {
    id: 'users',
    path: '/users',
    search: mergeSearch(
      paginationSearch,
      usersSearch,
    ),
    hash: userHash,
  },
] as const);
```

`mergeSearch()` rejects duplicate keys:

```text
Duplicate search descriptor key "page" passed to mergeSearch().
```

Silent overrides would make generated contracts lie.

### Path and index rules

A route must define either `path` or `index`, except for a pathless layout/group route with children.

Valid pathless group:

```ts ts2js
{
  id: 'dashboard.group',
  layout: {},
  children: [
    {
      id: 'dashboard',
      path: '/dashboard',
    },
  ],
}
```

Invalid pathless renderable route:

```ts ts2js
{
  id: 'entry.redirect',
  redirect: { route: 'overview' },
}
```

That route must define `path` or `index`.

Index route rules:

```ts ts2js
{
  id: 'dashboard.index',
  index: true,
}
```

Index routes cannot define `path` or `children`.

Static nested route definitions may use leading-slash child paths. They are still joined under the parent during validation and normalization:

```ts ts2js
defineRoutes([
  {
    id: 'policies',
    path: '/policies',
    children: [
      {
        id: 'terms',
        path: '/terms-of-service',
      },
    ],
  },
] as const);
```

The child full path becomes:

```text
/policies/terms-of-service
```

Modular parent-attached declarations are stricter. A declaration with `parent` must use a relative child path.

## Layout contracts

### `RouteLayoutDefinition`

```ts ts2js
interface RouteLayoutDefinition {
  readonly view?: RouteView;
  readonly loading?: RouteView;
```

`layout.loading`, `layout.error`, and `layout.slots` require an active layout view on the same route or an ancestor route.

This is valid:

```ts ts2js
{
  id: 'root',
  path: '/',
  layout: {
    view: RootLayout,
    loading: LayoutLoading,
    error: LayoutError,
    slots: {
      modal: true,
    },
  },
}
```

This is invalid:

```ts ts2js
{
  id: 'standalone',
  path: '/standalone',
  view: StandalonePage,
  layout: {
    loading: LayoutLoading,
    error: LayoutError,
  },
}
```

There is no active layout shell to own those layout fallbacks.

`route.loading` and `route.error` are route-local. `layout.loading` and `layout.error` are layout-owned and shared by descendant content.

### `RouteSlotDefinitions`

```ts ts2js
type RouteSlotDefinitions =
  Readonly<Record<string, RouteSlotDefinition>>;

type RouteSlotDefinition =
  | RouteView
  | RouteSlotConfig
  | true;
```

Slot values mean:

| Value             | Meaning                                                     |
| ----------------- | ----------------------------------------------------------- |
| `true`            | Declares the slot without fallback content.                 |
| `RouteView`       | Declares the slot and uses the value as fallback view.      |
| `RouteSlotConfig` | Configures fallback view, nested slot routes, and metadata. |

Invalid slot values:

```ts ts2js
false
null
undefined
```

## Intercept contracts

### `RouteInterceptConfig`

```ts ts2js
type RouteInterceptTarget =
  | string
  | readonly string[];

interface RouteInterceptConfig {
  readonly to: RouteInterceptTarget;
  readonly view: RouteView;
}

type RouteIntercepts =
  Readonly<Record<string, RouteInterceptConfig>>;
```

<TypeTable
type={{
to: {
description: 'Target route ID or route IDs this intercept can handle.',
type: 'string | readonly string[]',
},
view: {
description: 'View rendered into the configured slot during intercepted navigation.',
type: 'RouteView',
},
}}
/>

`intercepts` are keyed by slot name.

```ts ts2js
{
  id: 'overview',
  path: 'overview',
  layout: {
    view: OverviewLayout,
    slots: {
      modal: true,
    },
  },
  intercepts: {
    modal: {
      to: 'create',
      view: CreateModal,
    },
  },
}
```

Validation requires:

* the slot name is not empty;
* the intercept config is an object;
* `view` is present;
* `to` contains at least one non-empty target route ID;
* every target route ID exists;
* the source route or an active ancestor layout declares the slot.

Direct visits still render the canonical target route. Intercepts are navigation context, not a second URL.

## Static search descriptors

```ts ts2js
type RouteSearchSchema =
  Readonly<Record<string, StaticSearchField>>;
```

`search` uses URLKit-backed static descriptors. Route definitions must stay analyzable by the CLI, so use plain data instead of URLKit runtime builders.

```ts ts2js
search: {
  query: {
    type: 'string',
    optional: true,
  },
  page: {
    type: 'int',
    default: 1,
  },
  score: {
    type: 'number',
    optional: true,
  },
  featured: {
    type: 'boolean',
    optional: true,
  },
  tags: {
    type: 'string',
    many: true,
    optional: true,
  },
  sort: {
    type: 'enum',
    values: ['newest', 'popular'],
    default: 'newest',
  },
  publishedOn: {
    type: 'date',
    format: 'dd-MM-yyyy',
    optional: true,
  },
  startsAt: {
    type: 'date-time',
    format: 'dd-MM-yyyy HH:mm:ss',
    optional: true,
  },
}
```

Supported value kinds:

```text
string
number
int
boolean
date
date-time
enum
```

Descriptor properties:

| Property   | Applies to          | Required | Notes                                                                |
| ---------- | ------------------- | -------- | -------------------------------------------------------------------- |
| `type`     | all fields          | yes      | Parsed value kind.                                                   |
| `many`     | all fields          | no       | Only literal `true` is valid. `false` is invalid.                    |
| `optional` | all fields          | no       | Only literal `true` is valid. `false` is invalid.                    |
| `default`  | all fields          | no       | Cannot be combined with `optional: true`.                            |
| `values`   | `enum`              | yes      | Non-empty readonly string array.                                     |
| `format`   | `date`, `date-time` | no       | Built-in or static format string. Runtime codec objects are invalid. |

Invalid in route definitions:

```ts ts2js
search: {
  query: 'string',
}
```

Invalid runtime builder form:

```ts ts2js
search: {
  page: int().default(1),
}
```

Invalid runtime date codec:

```ts ts2js
search: {
  from: {
    type: 'date',
    format: {
      parse(value) {
        return new Date(value);
      },
      serialize(value) {
        return value.toISOString();
      },
    },
  },
}
```

Static date and date-time descriptors use UTC semantics. Use `toISOString()` or UTC getters when asserting parsed `Date` values.

Unsupported date format tokens are reported through URLKit with router route context. For example, `DD-MM-yyyy` is invalid for a two-digit day; use `dd-MM-yyyy`.

## Static hash descriptors

```ts ts2js
type RouteHashSchema = StaticHashDescriptor;
```

Hash descriptors are object descriptors. Do not use array shorthand.

```ts ts2js
hash: {
  type: 'enum',
  values: ['comments', 'share'],
  optional: true,
}
```

Supported hash kinds:

```text
string
enum
```

Hash values are bare values without a leading `#`.

Valid:

```ts ts2js
hash: {
  type: 'enum',
  values: ['comments', 'share'],
}
```

Invalid:

```ts ts2js
hash: {
  type: 'enum',
  values: ['#comments', '#share'],
}
```

Router URL builders add the leading `#` when generating hrefs.

Descriptor rules:

| Property   | Applies to           | Required | Notes                                                          |
| ---------- | -------------------- | -------- | -------------------------------------------------------------- |
| `type`     | all hash descriptors | yes      | `string` or `enum`.                                            |
| `optional` | all hash descriptors | no       | Only literal `true` is valid.                                  |
| `default`  | all hash descriptors | no       | Cannot be combined with `optional: true`.                      |
| `values`   | `enum`               | yes      | Non-empty readonly string array. Defaults must be in the list. |

## Preload contract

### `RoutePreload`

```ts ts2js
type RoutePreload =
  (context: RoutePreloadContext) =>
    void | Promise<void>;

type RouteModulePreload =
  () => void | Promise<void>;
```

`preload` is application-owned route warming. Use it for query caches, permissions, image warming, or other userland work.

`modulePreload` is for generated/runtime integrations. Most application routes should prefer `preload` or renderer helpers such as React lazy route views.

```ts ts2js
  preload: async ({ params, signal }) => {
    await queryClient.prefetchQuery({
      queryKey: ['user', params.slug],
      queryFn: ({ signal }) =>
        fetchUser(params.slug, { signal }),
      signal,
    });
  },
}
```

Preload does not commit navigation.

## Validation and normalization

```ts ts2js
function validateRoutes(
  routes: readonly RouteDefinition[],
  pathOptions?: RouterPathOptions,
): void;

function normalizeRoutes(
  routes: readonly RouteDefinition[],
  pathOptions?: RouterPathOptions,
): readonly NormalizedRoute[];

function validateResolvedRouteTree(
  routes: readonly RouteDefinition[],
  pathOptions?: RouterPathOptions,
): readonly NormalizedRoute[];
```

`validateRoutes()` validates a route tree and returns nothing.

`normalizeRoutes()` derives full paths, params, scores, order, layout slots, and intercept metadata. It validates path contracts while normalizing, but it is not full route-tree validation.

`validateResolvedRouteTree()` validates first, then returns normalized routes.

```ts ts2js
import {
  normalizeRoutes,
  validateResolvedRouteTree,
  validateRoutes,
} from '@cookbook/router/route-config';

validateRoutes(routes);

const normalized = normalizeRoutes(routes);

const validatedAndNormalized =
  validateResolvedRouteTree(routes);
```

Custom constraints are not accepted by these functions. Register them before calling, or use `defineRoutes()` / `defineRouteTree()` with `pathConstraints`.

```ts ts2js
import {
  registerPathConstraints,
} from '@cookbook/router/path';
import {
  validateRoutes,
} from '@cookbook/router/route-config';

registerPathConstraints({ slug });

validateRoutes([
  {
    id: 'post',
    path: '/posts/{slug:slug}',
  },
]);
```

## Where this bites

### `defineRoute()` does not validate anything

This compiles and returns the same object:

```ts ts2js
defineRoute({
  id: 'users.details',
  parent: 'missing',
  path: '/absolute-child',
} as const);
```

The error appears only when declarations are composed or validated.

### Static nesting and modular parent composition are not identical

Static nested route definitions can use a leading slash child path and still join under the parent.

Modular declarations with `parent` cannot:

```ts ts2js
defineRoute({
  id: 'users.details',
  parent: 'users',
  path: '/{slug}',
} as const);
```

`defineRouteTree()` rejects that. Parent-attached modular children must use relative paths.

### Layout fallbacks require a layout shell

This is wrong:

```ts ts2js
{
  id: 'standalone',
  path: '/standalone',
  view: StandalonePage,
  layout: {
    loading: Loading,
    error: ErrorFallback,
  },
}
```

There is no layout view in scope. Use `route.loading` / `route.error`, or declare `layout.view`.

### Slot fallback config is not React slot error isolation

Route config slot fallback:

```ts ts2js
layout: {
  slots: {
    modal: {
      view: EmptyModal,
    },
  },
}
```

React slot error isolation:

```tsx ts2js
<Slot name="modal" errorFallback={ModalError} />
```

One supplies route content. The other catches render failures. Mixing them up sends errors to the wrong owner.

### `validateRoutes()` does not receive custom constraints

This is wrong:

```ts ts2js
validateRoutes(routes, {
  pathConstraints: { slug },
});
```

`validateRoutes()` only accepts path options as its second argument.

Use `defineRoutes()` or `defineRouteTree()` with `pathConstraints`, or register the constraints before validation.
